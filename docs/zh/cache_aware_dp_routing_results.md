# 方案 A / B 高压 Prefix Cache TTFT 实测

> 历史实验记录：以下 A/B 开关及数据对应双策略实验版本。当前实现按要求仅保留方案 B，已移除 `--dp_routing_policy`；不能使用当前二进制切回 A。历史方案可通过提交 `07b2a09fc` 恢复。

## 配置
- Qwen3.5-2B，BF16，TP1，DP4/DP8；每 DP cache 512 MiB，block size 128。
- max_tokens_per_batch=2048，max_seqs_per_batch=32，chunk=256，prefix cache 开启，graph/overlap 关闭。
- 固定输出 256 tokens；4 组前缀，80% 重复输入、20% 唯一后缀；这不是 80% 实际 token 命中率。
- DP4：48 QPS、1024 请求/轮；DP8：96 QPS、2048 请求/轮；开放式泊松到达。
- 每组预热方式沿用此前脚本，每策略两轮，seed=42/43，同一轮 A/B 输入一致；顺序为 A→B、B→A。
- A=load_aware，B=cache_aware；B 阈值 10/1.5/0.5。使用同一新构建二进制。
- 本次为有限超载突发后排空，不是稳态 SLO 或无限时长容量测试。

## 解释与限制
- 本轮 B 的负载失衡分支触发次数均为 0；因此验证了本负载下缓存亲和选路的整体收益，但没有通过性能实验验证失衡兜底的效果，不能据此说明双阈值已调优。
- B 的缓存亲和分支（含预热）DP4 两轮分别触发 82/71 次，DP8 分别触发 1508/1543 次；DP8 收益更大与更频繁的缓存亲和及更高实际命中同时出现，不能仅凭相关性分离因果贡献。
- 不以结果反向修改参数或筛选成功轮次；完整保留原始请求、采样及服务端日志。
- 命中率按服务端正式请求的 num_prefix_cache_tokens 整数求和；排除输出为 8 token 的预热请求。
- TPOT 为客户端 (完成时间−首个非空文本时间)/255 的近似值，受网络与流式缓冲影响；固定 ignore_eos 输出长度。
- 完成吞吐按正式请求数/整个到达加排空时长计算，不是稳态最大吞吐。
- /vars 每 0.5 秒采样；U 为不可驱逐 admission pressure，不是整卡显存占用。
- 路由分支计数含预热，见 analysis.json；不能把预计命中当成最终命中。
- 每策略两轮，不宣称统计显著性或生产收益；旧版 block 选路实验数字不能与此次直接混比归因。
- 二进制 SHA256：`e4990eb68416240cdcc01a8b67fe5088517f80c0b8d0033b68b6a7abd6cf4f10`。
