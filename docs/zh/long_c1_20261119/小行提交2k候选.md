# 小行提交的 2k 候选：只移植 scatter，不叠加旧 context Graph

L0Q（R2Q 上仅 P 取消 layer progress 打印）快筛 1173.096 ms / 15.487114 ms/token / 17.016414 s。所有实际 P rank 未设置该变量，仍有正常 P 终态，三条 matched 2000/1024、正文和 732/1470 不变，基本题通过。此轮不再有 layer span，TPOT 合格但 TTFT、E2E 分别慢 108.079 ms、41.130 ms，不晋级。

当前有理由单独改善生成：P4Q 首字均值已低于 2k 门槛，TPOT 尚需 0.02477 ms/token，约 0.086 ms/294 块中的每块；DT6 独立采样 context cache 中位 1.529 ms/块。归档 P2_006 在旧 q4/256 主场景没有稳定 E2E 收益，但 D 2–6 行提交中消除通用 sort/nonzero 的机制已经过 **224 项 bit 检查和 48 次动态图**，不能把这些历史数字当作本轮 2k 计分。P2_010 的 scatter-only 和 context Graph 不是同一变量；**本轮不移植 context Graph**，也不运行旧 256 队列。

在本个人分支仅移植 P2_006 的五个生产文件增量和两个验证文件，移植前五文件 SHA 均与原 before 相同，移植后 **7/7 SHA 与 archived after 完全一致**。默认关闭 `XLLM_DSV41_DRAFT_SMALL_COMMIT`；启用后仅对 2–6 行 BF16 原位写，重复 slot 取最后有效行、越界忽略，旧 1 行和大行路径保留，TP 配置必须一致。计划在已有 CPU-only builder 重新构建；先以同一新 D ELF 的 OFF 核验 P4Q 轨迹，再只对 D 开启并复核基本题、显存、正文、accepted/proposed 和真实计分。P 保持原冠军 ELF、3072 桶保持 OFF。不把源码一致写成本轮构建或实机通过。

旁证更新：暂停的 P2_008 **历史** 256/256 独立诊断曾在同 SHA 的 Rust DSO 上直接测到三个慢请求 `tokenizers_new_from_path` 分别 182.707/192.463/187.478 ms，落在 router 入口区间内；其他七条无构造。这与本轮 H1D 的线程及字节数吻合。历史探针没有加载到本轮计分进程，也不是 2k 慢请求的函数计时。
