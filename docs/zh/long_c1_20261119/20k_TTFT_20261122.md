# 20k V4.1 1P1D 首字与生成调查

## 条件与参考

正式服务为 SJ9 P、SJ10 D，各八张卡。C1、原始文本由服务端分词、实际 20000 输入和 1024 输出 token、关闭思考、零 prefix 命中。每次独立启动一条暖机、五条计分。原生 token 终态与客户端 SSE 按 ID 对账，包含首正文、实际长度、唯一终态和投机统计。计分区间内双机没有编译，分析设备时间的 trace 独立运行。

## 首字关键路径

实际 20k 请求的 P 阶段约占历史 TTFT 的 97%。39 个块间空档共 0.26–0.32 s。逻辑分块增大后，继续使用原 512 行物理块、KV 写入和量化形状，减少每个逻辑块重复进入模型及最后几层的工作。三次同 ELF 独立启动按 512→1024→512 行得到 7816.748→5061.352→7717.803 ms。后续 1024→2048→1024 和 2048→4096→2048 均复现该方向。

中间块只补齐后续所需缓存，最后一块保留完整尾层与实际 logits 输出。同 ELF 的关闭、开启、回退 P 均值为 2223.5→1911.5→2229 ms，TTFT 为 2456.814→2148.384→2463.046 ms。独立设备流和六项物理缓存检查验证了选路，构建实际编译了嵌套的 DFlash worker 和 scheduler。8192 逻辑分块配合残差、上下文 KV、门控和压缩投影分片，以及宽块 SWA 写入进一步缩短暖后 P 路径。设备分析按单 rank 的设备事件区间计算，host marker 单独记录流程边界。

在较快的 P 路径上，Router 的懒分词器构造仍会间歇增加约 185–188 ms 的入口等待。预建模块使用同一 Rust FFI、同一模型文件，在 Router 进入 main 以前为 16 个线程用途准备独立实例，无请求和 token 缓存。作用域由 Router 可执行文件、实载 Rust SO、模型文件、映射和进程身份约束。模块源码在 `tools/musa_deepseek_v41/router_tokenizer_preinit.c`，配套同模型多线程对照在同目录。该路径启用后，受影响的入口等待缩短，暖后首字与 P 原生边界之差约 40–46 ms。

## D 端生成

L20RTIDT 独立设备事件显示实际 q6 验证图约 46.279 ms，相关 DSpark 整步约 54.374 ms。L20RTIKG2 在稳定暖后窗口抓取八 rank 的实际 GPU kernel 时间线；rank 0 的 40 次 SWA 验证读取合计 3.104 ms。只将压缩行复制改为选中行复制，在同正文、同投机的独立开关回退对照中没有降低端到端耗时。

服务已有的验证读取同时生成严格合法的稀疏索引。按 query 并行生成连续 int32 的对齐索引，保留原索引顺序和 -1 哨兵，让同一 H8 MATE kernel 直接使用，去掉重复的范围检查、中间掩码和类型转换。原接口及未满足条件的路径继续走统一校验。设备对照的 14 种布局及 6 条输入变更后的 Graph 回放，KV、索引、提交槽和输出均逐位一致；合并读取与 H8 的设备中位数在压缩容量 10752 和 21504 分别为 0.131148→0.056312 ms 与 0.132673→0.057985 ms。

同 ELF 的 L20DNP0Q / L20DNP1Q 只改变 D 的索引准备开关。相同正文和相同 718/1530 接受/提议的样本从 16.614672 降到 15.480266 ms/token。两条完整快筛的均值从 17.343315 降到 13.704672 ms/token，均值同时受到生成投机工作量变化影响。开启组 TTFT 1622.919806 ms、E2E 15.642799 s。快筛据此预登记独立 F/R。

基础正确性范围是两道算术 4.2、56，以及涉及变更的缓存、路由、KV、索引、SSE 和设备 Graph 检查。


## 第一轮正式验证

L20FX1 与 L20DNP1Q 的配置和实载资产指纹一致，P、D 与 Router 分别独立启动。一暖五测原件均通过长度、SSE、原生终态、投机和基本算术审计。五条正式样本均为相同正文及 718/1530 接受/提议，均值为 1619.917424954474 ms、15.428396465688332 ms/token、17.403167009353638 s。TPOT 高于 SGLang 门槛 1.066861015162772 ms/token。这次预登记没有执行 R。双机各八卡于 10:24:40 释放，逐条资料归档在 `goal20k200k_20261119/cases/L20FX1`。

## 通过验收的 C1 配置

归一化索引之后，以同 ELF 的回退对照确认 D 的共享专家可以与 routed 分支重叠。独立设备事件又确认 Q/KV 投影重叠减小了每五提议的验证耗时。长索引优化保留稳定分数排序，随后合并选中 512 个索引的位置排序、有限分数与可见范围判断、int32 写回。并行专家路由保留稳定并列顺序和原权重归一化。从同一 ELF 依次打开这两个开关，L20DFR0Q、L20DFR1Q、L20DFR2Q 的 TPOT 分别为 15.064464386312231、14.381374263424037、14.338270624970265 ms/token。按实际提议量归一化，生成耗时分别为 49.62690396570922、48.07890807674114、47.86089770744583 ms/五提议。独立 D 设备校验覆盖融合索引的 40 个变体与 12 次变输入 Graph 回放，以及门控的 40 个变体与 8 次 Graph 回放。全部保留逐位可比较的索引、专家 ID 和有限权重。早期以 muDNN INT64 TopK 替代稳定分数排序的候选在设备检查明确返回不支持，原始失败记录归档。

正式两次分别新起 P、D 和 Router，和 L20DFR2Q 的实载身份及角色资产一致。两个独立启动各计五条，未舍入指标各自过全部三方门槛。

## MATE 0.2.8 的实际运行边界

MATE 试验开始于 0.2.6 正式 F/R 各自过线之后。基线两端的软件包分别核验了 `mate==0.2.6` 和 `mate-mubin==0.2.6`，C++ 角色实际映射六个原生库。候选使用官方 `v0.2.8` 源码和固定 mutlass 提交。发布的五份内核清单和 552 个对象内容逐一校验后打包为精确 `mate-mubin==0.2.8`。从 `0.2.8.post1` 取得的对象须匹配官方 `v0.2.8` 清单；候选 Python 包和原生代码均来自精确 `0.2.8`。 [MATE v0.2.8 发布](https://github.com/MooreThreads/mate/releases/tag/v0.2.8)

基于原 Torch、Torch-MUSA、TileLang 和 TVM-FFI 重建 mHC m32/m64、W4A8 group128/static 和 H8/H64 稀疏内核。当现有 C++ 包装只传九个参数时，0.2.8 H8/H64 设备检查明确拒绝，要求额外的 KV 字节跨度 `kv_span_bytes`。可独立构建的 `tools/musa_deepseek_v41/sparse_mate_028_abi.cpp` 适配层按 BF16 KV 的真实形状和步幅计算跨度，调用同目录带校验的原版重建 provider。适配使 C++ 服务 ELF、模型、词表和其余配置能够在升级前后保持一致。mHC、两种 W4A8 和 H8/H64 已完成相关数值与 Graph 检查。

原生包及库的来源、编译参数、动态符号、实载身份、脱离服务的设备验证与服务原始回执由本地交接的 `07_MATE升级` 和共享 NFS 的 `goal20k200k_20261119/mate_eval_028` 归档。


## MATE 版本决定

升级后使用同一 ELF、模型、词表和其余运行配置。P/D 逐 rank 复核实载库，P 使用候选 mHC m64、group128 和 H64 provider，D 使用候选 mHC m32、static 和 H8 provider。两个稀疏 provider 均附带九参到十参的适配层。基础镜像的 Python site-packages 保持隔离，正式 C++ 测试由这些已重建并检查实载的原生库体现版本差异。

两轮分别通过全部冻结门槛。相对 0.2.6 的对应轮次，首字缩短 37.60396558791399 和 43.73566284775734 ms。其中 P 原生阶段分别缩短 40.4 和 42.8 ms。TPOT 和 E2E 两轮均较低。相同正文与 718/1530 相同接受/提议量的样本，F 从 14.285608 降到 14.175937 ms/token，R 从 14.163420 降到 14.111709 ms/token。每五次提议的生成耗时在两轮分别变动 −0.163 和 +0.033 ms。稳定收益集中在 P 首字路径，生成段的估算收益较小。

保留正式通过的精确 **MATE 0.2.8** 运行方案。运行覆盖清单 SHA-256 为 `44655897f7a42a0118e23a4029ce1a5dab46936d31bb1b3cbf9bb5be5ac41cc5`，原生工件在自有共享 NFS `goal20k200k_20261119/mate_eval_028/abi-r1/artifacts`。P 将 mHC 路径指向该根下的 `mhc`，W4A8 指向 `group128/libdeepseek_v41_w4a8_group128.so`，H8 与 H64 分别指向 `sparse-h8/libdeepseek_v41_sparse_h8_bf16.so` 和 `sparse-h64/libdeepseek_v41_sparse_h64_bf16.so`。D 使用同一 mHC 目录、H8 路径和 `static/libdeepseek_v41_w4a8_static.so`。每个稀疏适配库与该目录下的 `libmate028_sparse_provider.so` 配对。保留 0.2.6 的基线原件供复验。

全部四轮的请求级记录、实际数据边界、SSE、独立原生终态和编译窗口均可复算。最后的只读审计确认 SJ9/SJ10 各八张卡为 0 MiB，GPU 进程表空，固定角色容器仅保留 idle shell，任务构建容器均退出。提交文件与正式 ELF 的构建清单核对了 31 个生产源文件。其中 5 个在独立提交工作树按仓库 clang-format 20.1.6 调整空白，经词法 token 和预处理指令核对，构建输入原件保留在现场归档中。正式性能由上述 SHA-256 对应的实测 ELF 提供。
