# xLLM：按阶段绝对耗时选下一项（非线性拟合）

**本文件记录用户重排前已完成的曲线，不授权新 8k/20k 实验；当前门槛见[当前2k放行条件](当前2k放行条件.md)。**

使用冠军 ELF、P chunk256、DSpark3；每种长度重启服务、另做一次暖机。本表不使用 trace 时间。2k/20k 各列一组当时的独立控制；8k 仅探点，不把两条样本当正式冠军。

|实际输入/输出|组|计分 n|TTFT ms|TPOT ms/token|E2E s|计分 E2E 范围 s|
|---|---|---:|---:|---:|---:|---:|
|2000/1024|A3|5|2036.634|16.939|19.365|19.222–19.705|
|8000/1024|X8K|2|7523.627|39.576|48.010|43.834–52.186|
|20000/1024|X20K1|5|19838.498|35.772|56.434|55.243–58.684|

- P rank0 模型实际分块数 8、32、79；增加到 512 后不仅少调度，也会改变计算形状，不能假定输出不变。20k 绝大部分首字预算在 P 的模型区间。2k 中 512 已证明能减少 P launch，但整体不稳；20k 必须重新验证，不能以 2k 不晋级直接否决。
- 8k 的两条正文 SHA 不同：第一条 642 accepted / 1152 proposed，E2E 52.186 s；第二条 695/993，43.834 s。20k 的 701/975 即使上下文更长，也不必 TPOT 更慢。2k target Graph 可以命中；8k、20k 超过 4096，不能用这三个点去拟合“每多 1k token 多多少 ms”。不能将 8k 的差解释为设备随机慢了 8 s。
- 20k 旧冠军相对 SGLang F2 的生成阶段多约 19.8 s，比 TTFT 差约 12.6 s 还大。20k/32 D-only 独立 trace 在一个 rank 记录约 9.88 万个 kernel；因启动/同步被 profiler 放大，不把 custom reduce 的毫秒数视作可回收预算。优先在现有数值/图合同内试增加每轮提交的输出，即 (3→5) 个提议。native 模式 master 允许 1–5；2k target verify 时行数从 4 变 6、仍在图支持范围；20k 仍为 eager。分别记录每一条流、verify 工作量、E2E 和两道题，不重编冠军，不先改通信实现。
- P/D 现有 `[Mooncake][PDTransfer]` 记录里有 regions=0、packed_regions=0 的 pull；只说明这条调用没有这些 region，不能推成全请求传输零字节。D 还记录 selective commit 的本地 checkpoint（201232 bytes），这也不是 P/D 网络字节。本轮没有所有状态通道的精确线速计数；没有将跨机时钟直接相减。后续若传输成为瓶颈，改在相同 request_id 的 pack/send/ready/restore 边界分别记 bytes、主机单调时长。
- PCP：P 端首字预算足够大，值得保留研究方向；当前没有度量出 CP2/4 预期节省大于通信，也没有验证 V4.1 的 CSA2 Indexer、CED 尾部、Engram、MoE 和 P/D 全局状态分片合同。不把 CP 句柄大小说成已启用；本次不移植其他模型的 PCP，不改变单 P 八卡拓扑。
