# 给家明：2k/1024 的 chunk 快筛

SJ9 P / SJ10 D，每侧 8 卡、1P1D、1017 W4AFP8-mt、C1。没有重编、没有合入短序列的 dirty 候选。两侧同一个 E52 ELF（源码 980d9da1、SHA-256 7d2ffa0662fd53f0074d6f29c7a28e0f4db5e057cb1c0ad6febc706bfc74303f）。新分支以 e6d3cdd1 为基点，提交的是**诊断和对照证据**，并非新二进制。

**快筛结论：首字省了 762 ms，并不等于整条请求省 762 ms。** 1023 个后续间隔多用约 561 ms；最终仅净省 201 ms（1.04%）。以同一文本、同一 EvalScope 计时边界，按 SSE id 一一对上原生终态：每个请求都是实际 2000/1024、length、前缀命中 0。A0 正文哈希 f3a68e08…，接受/提议 690/1008；B1 为 a7f8e193…、675/1050。两组各自内完全一致，组间轨迹不同；不能归因为 D 内核变慢。两道基本题在 B1 补齐到 2000 输入、正常 EOS，分别回答 4.2、56。**仅通过基础功能检查，未完成模型精度验收。**

### 改动与证据
- 只改 P 全 8 rank 的 `max_tokens_per_chunk_for_prefill` 和 `max_tokens_per_batch`（共同决定有效 chunk），256 → 512；D 的执行参数不变。独立进程/namespace；未改模型数学逻辑。
- 新工具 `tools/musa_deepseek_v41/audit_long_c1.py` 检查原始 DB 的每个正文、结束原因与服务端精确 id，输出哈希和投机计数。历史 2k 与 20k 各 1+5 已离线验证。20k 接受/提议为 701/975，高于 2k 接受比例；这批 20k 的高 TPOT **不是接受率变低**就能解释的。
- `long_prefill_stages.py` 读取同一 P rank0 现成的 layer begin/enqueued 日志。A0 实测 7×256+208，B1 实测 3×512+464。两条计分请求 P 侧阶段 TTFT 为 1822/1814 → 1050/1066 ms；窗口内不跨机减时间戳。日志为 host span、非 GPU 独占时长。
- 独立 2000/8 的 trace 只做归因，不作为 1024 输出的性能。每侧各 8 个 trace 与 stack，`long_trace_rank.py` 取单 rank kernel 区间并集。P rank0 kernel 数 61208 → 30592，BF16/FP32 ring all-reduce 分别由 320 次降到 160 次。原始 trace 严重扰动：同诊断客户端 A0 开/关约 20.67/2.03 s，B1 17.57/1.27 s。不能把 profiler 下的 collective 毫秒数当作可消除 E2E。
- 共享盘证据入口：`xiaopang/v41_xllm_match_sglang_20261116/long_opt_20261119/` 的 `00_control/A0`、`01_candidate/B1`（basic_2k、performance、各端 rank0.log、trace/manifest.json）、`02_trace/{A0,B1}`。11/18 历史目录不变。所有数字都不用 profiler 与非 profiler 混算。
- SGLang 20000/1024 仍 F0；xLLM 历史 56.781 s 仅是自身基线，尚无新窗口 20k 对手值。历史 C48 manifest 不作为本机比较的门禁。PCP 未启用。

### 2k 正式判定：不晋级
三组均为独立新服务 1 暖 5 测，正反向使用相同 ELF、请求、C1、计时和 ID/终态核验。

|---|---:|---:|---:|---:|---:|---|
|A1r（控制）|256|1975.172|16.934|19.299|53.060|19.231–19.352|
|B2（候选）|512|1268.691|17.569|19.242|53.217|18.897–19.392|

B 的首字相对两个 A 均可重复缩短 668–706 ms；但 1023 个生成间隔变慢，固定文本正文和接受/提议的变化在独立重启后完全复现。整条请求对 A1r 快 57 ms，对 A2 **慢 122 ms**，提升方向不稳定，TPOT 对两组均退化。保留 256；512 是首字优先的可选取舍，不是累计冠军。不把 5 条样本解读为可靠 p99。A1 初次门禁看见刚退出的 B1 GPU PID，未发起启动；等显存正常释放后另建 A1r，没有强制清理。原始目录 `00_control/A1r`、`01_candidate/B2`、`00_control/A2`。
