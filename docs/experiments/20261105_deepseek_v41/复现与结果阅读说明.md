# 本轮 0909 两机 1P1D：复现与结果阅读

这份说明针对本任务已准备好的开发镜像、源码、原生二进制和模型视图。结果阅读不需要重跑模型。当前原始实验 ID 是 `pd_dev4_dev7_v2_nic9`；最终是否通过以 `performance_v2/validated_summary.json` 为准，不能只看客户端退出码。

## 1. 先阅读哪些文件

1. `适配说明.md`：已经接通的结构、MATE 与 TorchMUSA 的区别、未完成的量化/融合能力。
2. `raw/runs/pd_dev4_dev7_v2_nic9/basic_questions/answers.json`：两个真实题目、完整答案、原生 usage 与结束原因。
3. 同一 run 的 `basic_pd_path_evidence.json`：请求确实经过 P 与 D，D 八个 rank 的缓存拉取成功记录。
4. 同一 run 的 `performance_v2/简要性能结果.md` 和 `measured_per_request.csv`：两组均值及全部 10 次结果。预热另存，不混入均值。
5. `performance_v2/raw_measured_256_256.jsonl`、`raw_measured_2048_256.jsonl`：工具保存的原始请求/响应、每条对应 P/D 日志及核验情况；原始 SQLite 同时保留。
6. 两端 `final_archive.json`、`result.json`、`gpu_after_stop.txt`：正常退出情况及退出后的显存状态。

NFS 上相同原始实验位于 `/data/nfs_shared/xiaopang/deepseek_v41_flash_1p1d/20261105跑通PD分离/runs/`。本地的 `运行记录/` 对应 NFS 的 `runs/`，`证据/` 对应 `evidence/`。Git 中精选原始证据位于 `docs/experiments/20261105_deepseek_v41/raw/`。

## 2. 本轮固定配置

- P：dev4，D：dev7，各 8 张 S5000；attention TP8，专家 EP8/MoE-TP1，EP 组仅在各自主机实例内。
- eager，关闭 graph、MTP、prefix cache、自定义 TP all-reduce；TP/EP 使用 MCCL，P/D 使用 Mooncake PULL。
- Mooncake 只用 `mlx5_9`，避免第一次自动选到管理网 bond 的失败。它不是 MCCL 网卡设置，也不是最优多 NIC 带宽配置。
- 每组 C1，预热 1 次，正式 5 次；输入由官方 encoder 精确构造为 256 或 2048 token，实际输出均须为 256。
- temperature=0、top_p=1、reasoning_effort=none、thinking_mode=chat；正式测速 ignore_eos=true，以便测固定生成长度。基础算术题不启用 ignore_eos，要求正常 stop。
- 性能题目要求用英语解释“为什么工程师应保存实验记录”，后接明确标为 padding 的 `x` 字符。两种长度不是两种精度题库；完整文本、模板后文本、token IDs 与 SHA 在 `artifacts/benchmark_inputs_v1/`。
- 镜像为 `registry.mthreads.com/presale/devtech/xllm:1102-dev`，实际运行的是我方重新编译的 `/work/artifacts/bin/xllm` 和 `/work/repos/xllm-musa` Python 源码。
- 二进制 SHA256：`7265c5997a5877d548178a3c80522034e3aeac6e5d3358763878588bf8bbfbb9`；本轮运行过程中未更换模型计算实现。

## 3. 再次运行前的前提

使用现有访问指南登录服务器。先确认两台服务器获准使用且各八张卡全部空闲，不停止他人的容器。dev4 本任务 Docker socket 是 `unix:///run/xiaopang1105-docker-dev4.sock`，dev7 使用默认 socket。dev4 独立 daemon 未设为自动启动服务；若将来主机重启，应先按保存的配置恢复本任务实例并确认与系统 daemon 的隔离，不直接重启系统 Docker。

下面命令是复现模板，不表示应立即重新启动。选择新的 run ID，避免覆盖本轮证据。若改机器或网卡，必须重新检查物理网络与资源，不直接照抄 dev4/dev7 的配置。

在 dev6 的 CPU 构建容器生成配置：

```bash
docker exec xiaopang1105_dsv41_build_dev6 python3 \
  /work/scripts/prepare_role_configs.py \
  --prefill dev4 --decode dev7 \
  --run-id pd_dev4_dev7_replay01 \
  --mooncake-rdma-devices mlx5_9
```

在 dev7 主机先启动 D（启动脚本会再次检查八卡空闲、镜像 ID、端口、RDMA 网卡）：

```bash
task_root='/data/nfs_shared/xiaopang/deepseek_v41_flash_1p1d/20261105跑通PD分离'
sudo python3 "$task_root/scripts/launch_role.py" \
  --config "$task_root/artifacts/prepared/pd_dev4_dev7_replay01/dev7.json" \
  --run-id pd_dev4_dev7_replay01
```

在 dev4 主机启动 P：

```bash
task_root='/data/nfs_shared/xiaopang/deepseek_v41_flash_1p1d/20261105跑通PD分离'
sudo python3 "$task_root/scripts/launch_role.py" \
  --config "$task_root/artifacts/prepared/pd_dev4_dev7_replay01/dev4.json" \
  --run-id pd_dev4_dev7_replay01 \
  --docker-host unix:///run/xiaopang1105-docker-dev4.sock
```

等待两端加载完成、两端健康检查与 Router `/readyz` 都通过，再在 CPU 容器执行基础题：

```bash
docker exec xiaopang1105_dsv41_build_dev6 python3 /work/scripts/check_basic_questions.py \
  --url http://10.20.34.28:29080/v1/chat/completions \
  --output /work/runs/pd_dev4_dev7_replay01/basic_questions \
  --binary /work/artifacts/bin/xllm
```

只有两题均 PASS，才使用同一端点、同一二进制执行官方工具：

```bash
docker exec xiaopang1105_dsv41_build_dev6 python3 /work/scripts/run_official_performance.py \
  --url http://10.20.34.28:29080/v1/chat/completions \
  --gate /work/runs/pd_dev4_dev7_replay01/basic_questions/basic_gate.json \
  --output /work/runs/pd_dev4_dev7_replay01/performance_v1
```

本轮还人工建立了 `basic_pd_path_evidence.json`，通过 P/D 日志的原生 request_id 和每个 D rank 的传输记录证明真实双机路径；重跑时也要重新建立该证据，不能复制旧 run 的成功结论。`summarize_performance.py` 要求它存在，并且逐条核对正式请求的 P/D 日志。

## 4. 停机、汇总与保留

客户端全部完成后，通过该 run 两个主机目录中的 `stop.request` 请求 supervisor 正常 TERM。不要照抄旧 run 路径，不连续重复 stop/kill；若不能正常退出，应先保留日志、检查线程和设备状态再决定处理。本轮专用 `stop_completed_pd.py` 硬编码了原始 run 且有完成检查，不能直接用于新的 replay run。

等 16 个 rank、两个推理容器均正常退出后，归档状态和 GPU 报告，再执行汇总。这能让报告中的服务端日志 SHA 对应不再追加的最终文件。当前汇总会拒绝覆盖已有 raw JSONL；重复生成时应先归档旧派生结果，不能删除原始 SQLite/服务日志。

本轮保留停止状态的 P/D 容器便于复查；dev6 CPU 构建容器保留开发环境。旧失败容器只有在完整归档、正常退出后才清理。模型权重、开发镜像、独立 Docker data-root、私有 MATE 源码均不进入 Git，也不应将整个 `artifacts/` 当作轻量报告打包。
