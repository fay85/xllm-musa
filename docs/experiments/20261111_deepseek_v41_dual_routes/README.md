## 本分支的实现和证据

这条分支增加原生 CausalLM factory、检查点映射、Decoder、CSA2 Attention、Engram、MoE 和 LM head。外层使用 xLLM 的调度、进程组和 Mooncake。模型 forward 由 C++ 执行。

两路都使用原版 1017（HF revision `1bae0e1088993b9b82de08f59de5be5a34e42170`），从 1103 共同祖先 `0cfd82700e164e8aa7951064b652925dd6b24d18` 开始，MATE 版本为 0.2.7。二进制 SHA256 为 `aaae381a887ea5bc288fb3ffb728021cb4f4b1b553fe37cfed9a93b4748513d3`。

共享 SwiGLU、mHC 三原语和 partial RoPE 沿用家明 V4 的实现。GPU 路由按 V4.1 的 sqrt-softplus 与 top-6 规则计算。小 M 路由专家直接使用 packed FP4。大 M 在 GPU 上使用 BF16 尾数的分区 BMM 并施加原始 group32 scale。原始 FP4/group32 直接 grouped GEMM 仍受当前 muDNN 量化分组接口限制。CSA2 的原始量化经 QDQ 计算，缓存物理载体为 BF16。Engram gate 融合参考京东交付 SGLang，表与 hash 使用原版模型资产。

两道基础题均答对。每路线的八个 D rank 各有 14 次成功的非空 Mooncake pull，包含基础题和两组正式测试。原始 SQLite、完整 rank 日志、请求、SSE 基础题和环境清单保存在共享盘 `20261110_night_dual_routes/cpp/benchmarks/night_cpp_native_v3/`。此目录下的 `raw/` 包含本分支的复核摘要和逐请求数据，SHA 见 `raw/files.sha256.json`。


我另外用独立诊断构建核对了数学短题和原 256 token 性能样本。与已归档的 Python 诊断相比，按 P 对 P、D 对 D 分别检查实际输入，40 层末行 hidden、pre_mix、最终 hidden 和 129280 项 logits 均逐值一致。P 与 D 的对照则在第 0 层 Attention 归约后首次出现差异，两道样本的该处最大绝对差均为 0.03125。原性能样本的全词表 logits 最大绝对差为 2.5，下一 token 均为 15170。归约前采集范围为 rank 0，区分其余 rank 输入差异和 MCCL 归约顺序还需要逐 rank 观测。原始诊断归档在共享盘 `20261110_night_dual_routes/cpp/correctness/native_prefix_audit_round/`。
