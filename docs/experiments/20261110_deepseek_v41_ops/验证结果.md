## 性能：包含 Python 绑定与拼接开销

单位全部为 **µs/调用**，表中为 5 个样本的 wall time 中位数。激活测试每个样本 50 次调用，完整共享 MLP 每个样本 10 次调用；两者各先暖机 10 次。原始 JSON 同时保存每个样本的 wall time 和 device event time。

完整 MLP：hidden=5120，三次 BF16 GEMM（gate/up/down），相同输入与相同随机权重，仅激活实现切换。**I=2304 是当前共享专家宽度；I=288 是补充维度，不代表当前代码已经把共享专家按 TP8 切分。**

| tokens | I | reference 激活 | fused 激活（含 cat/分配/绑定） | reference 完整 MLP | fused 完整 MLP | 完整 MLP 耗时减少 |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 288 | 78.43 | 23.69 | 163.43 | 103.18 | +36.87% |
| 1 | 2304 | 77.87 | 23.38 | 168.10 | 105.76 | +37.08% |
| 256 | 288 | 79.25 | 26.09 | 163.15 | 104.41 | +36.00% |
| 256 | 2304 | 78.05 | 33.47 | 167.48 | 153.07 | +8.60% |
| 2048 | 288 | 77.81 | 47.66 | 187.31 | 193.16 | -3.12% |
| 2048 | 2304 | 108.28 | 252.10 | 679.34 | 771.15 | -13.51% |

结论：单 token、I=2304 的完整共享 MLP 从 168.10 降至 105.76 µs，减少 37.08%；但 T=2048、I=2304 从 679.34 增至 771.15 µs，增加 13.51%。因此本次不全局开启 fused。后续真实部署 A/B 优先评估 decode 侧；prefill 保留 reference，之后再按实际 chunk/token 形状验证选择策略。I=288、T=2048 下完整 MLP 的小幅变慢也如实保留，不能拿激活单项更快来覆盖全段结果。

这不是 TTFT/TPOT/token/s 的结果。当前路由专家仍有逐专家解量化、BF16 GEMM 和 Python 循环；本项只改 shared activation，不能据此宣称整模型速度增加 37%。

## 失败与修正

1. 独立测试扩展最初缺少 xllm 头文件搜索目录，报找不到 `core/runtime/py_musa_kernel_bindings.h`。修复测试 target 的 include path；保留 [构建失败日志](raw/build_v1_missing_include.log)。
2. 初版复用 kernel 的 10 组有限值输入通过，但 NaN/Inf 组合有 24/169 项不符合参考。原 `fminf/fmaxf` 不保留 NaN；改为保留 NaN 的比较选择，再重编。保留 [数值失败日志](raw/v1.log) 和 [失败时分项记录](raw/v1.json)。其中初版 mismatch 计数包含 NaN!=NaN，最终脚本已修正统计，精确失败数以 assert 日志为准。
3. 未通过降低阈值掩盖差异，也没有改变路由权重的 FP32 乘法位置。最终 [构建日志](raw/build.log) 和 [退出码](raw/build.exit) 为成功。

## 复验命令

使用匹配镜像、已配置的 MUSA CMake 构建树：

```bash
bash scripts/ninja_safe.sh build/cmake.linux-x86_64-cpython-310 -j4 xllm musa_python_kernel_test_module
# PYTHONPATH 需包含测试扩展的产物目录及仓库根目录。
python3 -m pytest -q tests/python/test_deepseek_v41_musa_shared_swiglu.py tests/python/test_deepseek_v41_packed_experts.py
python3 tools/musa_deepseek_v41/validate_shared_swiglu.py --output result.json
python3 tools/musa_deepseek_v41/validate_csa2_fixture.py --output ref.json --shared-swiglu reference --save-tensors ref.pt
python3 tools/musa_deepseek_v41/validate_csa2_fixture.py --output fused.json --shared-swiglu v4_fused --save-tensors fused.pt
python3 tools/musa_deepseek_v41/compare_swiglu_fixtures.py ref.pt fused.pt compare.json
```

GPU 验证要求容器内仅暴露一张空闲卡。上面的构建命令针对已有正确配置的构建树；完整本轮环境脚本见 [build_shared_swiglu.sh](raw/build_shared_swiglu.sh)，实际启动命令及隔离检查见 [launch_single_gpu.py](raw/launch_single_gpu.py)。启动脚本检查卡是否空闲后才运行，不停止他人的容器。
