# H200 原版1017：首轮双机PD同Token测速

北京时间2026-11-12 09:50完成。本文件记录第一轮原始结果，不删除首Token异常样本，也不据此宣称达到60% SOL。

## 测试条件及可比范围

231为P、232为D，每台8张H200，TP8/EP8，C1，eager、关闭graph/overlap/prefix cache/MTP；prefill chunk256，context和max_total_tokens4096，SWA bounded replay关闭，采用完整prefill。SGLang镜像`lmsysorg/sglang:v0.5.23`，源码标签`297e54fd105e974cdf401e5b4d20253a22c16f90`，Torch2.14.1+cu130。

使用官方原版1017：`/data/NFS_Storage/models/DeepSeek-V4.1-Flash-1017`。此前已完成83文件、48权重的全SHA256/索引/双节点验收。Hopper专家路径由SGLang选择`flashinfer_mxfp4`。

客户端为未修改的EvalScope1.14.1 perf，与MUSA相同版本。每组独立1次暖机、5次正式请求，固定相同的原始题目、完整渲染Prompt以及输入Token ID向量，实际输入分别为256/2048、实际输出均为256，temperature=0，top_p=1，ignore_eos=true，streaming。NVIDIA接口为`/v1/completions`，MUSA为chat接口；已逐个核对其实际送给模型的Token ID相同，避免只比较字面Prompt。基础问答4.2与56都通过。

两端权重数值形式与推理框架不同：CUDA原版FP4、MUSA为MooreThreads W4AFP8-mt转换权重；因此是当前部署方案的实测参考，不是纯硬件隔离实验，也不等于完成完整精度对齐。

|256/256|651.44|132.82|34.5212|7.4157|0.0290|

正式请求原生usage和DB逐行检查全部通过，最终标志`PASS_ALL_FOUR_PHASES_EXACT_NATIVE_TOKEN_COUNTS`。256组有一次TTFT2352.65ms，其余180.55～249.35ms；2048组最后一次TTFT18993.35ms，其余1453.84～1630.87ms。两组TTFT中位数分别237.91ms、1620.70ms。异常请求的TPOT仍约132.6～132.9ms，额外延迟主要集中在首Token前。原因尚需结合服务/路由日志定位，不擅自将它们剔除，也不把中位数替换官方均值。

MUSA StageH同样1+5两组的平均TPOT为205.17/207.13ms，对应H200约132.82/132.72ms；当前MUSA的输出吞吐约为该轮H200的65.49%/70.42%。这只是跨部署方案实测比值，**60%×H200速度不能称为摩尔GPU的60% SOL**。SOL需要以实际SJ GPU的计算、访存、通信能力和该模型各阶段工作量建立上限；尤其C1 decode可能受访存/launch/通信约束，不能只用峰值算力折算。
