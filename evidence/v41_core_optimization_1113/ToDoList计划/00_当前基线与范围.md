## 2. 当前运行口径

SJ9 为 P、SJ10 为 D，各 8 张 S5000。Attention TP8；路由专家 EP8，每 rank 48/384 个专家；共享专家复制计算，在路由专家归约后只加一次。当前是文本、并发 1、eager、chunk/batch 256、max-seqs 1、cache 1 GiB、block128；prefix cache / overlap / Graph / MTP 均关闭。当前 EP 是各 rank 持有同一请求 token、计算各自专家、合并后 F32 all-reduce，不是已完成 DeepEP 的分发/回收方案。

正式测试使用原版 EvalScope 1.14.1：1 次暖机、5 次正式；temperature=0、top_p=1、reasoning=none、ignore_eos，核对实际输入长度及 256 个输出 token。正式测试关闭 profiler；已有详细 trace 是独立的 256 输入/8 输出捕获场景。进度日志及 MCCL trace buffer 65536 属于 H/I 一致的有效配置，不得偷偷去掉后直接与旧成绩比较。

环境基础为 `xllm:1102-dev`、Torch/MUSA 2.9.1、基础 MATE 0.2.7、任务隔离的交付扩展与 AOT。Python 用于离线构建、tokenizer、启动和测试；实际逐层 forward 在 C++/MUSA GPU 上。不要将所有依赖笼统写成“最新 MATE”。逐库版本及 SHA 以运行包 manifest 为准。

上次确认保留的我方容器是 `xiaopang1112_v41_prefill_sj9`、`xiaopang1112_v41_decode_sj10`。这些名称是恢复入口，**本次未重新查询它们的实时状态**；后续执行前先确认归属、服务用途及资源占用。

## 4. 已经接入与仍需优化的区别

已具备：真实 40 层、W4A8 路由专家、共享专家、Mega-mHC prepare/post、RMSNorm/RoPE、MATE 稀疏 Attention、CSA2/Indexer、C2 compressor、Engram hash/lookup/injection、P/D 状态映射、wo_a 单 token GEMV、SWA 单 token scatter。详见 [当前算子覆盖](依据/固定基线/operator_coverage.md)。

仍有优化空间：缓存地址计算/gather、通信选择和等待、mHC 周边组合、Dense QDQ 与矩阵计算组合、Graph、并发、DeepEP/CP/DP、CED bounded replay、DSpark。后两项会改变执行或接受机制，不能伪装成一个简单无损 kernel 替换。完整多模态及官方全量精度也不在本轮已验收范围。

## 5. 必须保留的边界

1. 2048 固定 prompt、temperature=0 下，H 的 5 次输出有 3 种、I 有 4 种；只一对逐题完全相同。尚不能声称完整精度验收通过。用户此前允许记录问题后继续性能，本计划保留目标前缀/算子回归，不擅自重开全量 MathQA100。
2. 无 progress 的早期长请求曾超时；尚未完成与日志、调度时序、通信的隔离。不要称“开日志修复死锁”。在稳态比较期间先保留配置；另建诊断分支处理。
3. 新增领导聊天是**安排** toolkit 从 2.1.0-1 升到 2.2.0，不是证明升级已完成。后续要记录实际版本及 libmtml 映射；如已变更，在新环境重新测同一个 I，再比较新代码。不自行升级驱动/toolkit，不重启共享主机。
4. SJ11/SJ12 外部独占限制仍有效，旧“某晚九点前可用”的授权不能延用到现在。H200 231/232 任务已释放资源，H20 201/202 性能任务仍延期；本计划不重新占用。
5. NFS 名称相同不代表同一物理共享盘：SJ 与 DEV 根源不同。新实验记录物理 mount 源，统一在对应盘的 `xiaopang/` 下落盘。
