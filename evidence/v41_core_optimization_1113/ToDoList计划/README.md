编制日期：2026-11-12。性质：**已有证据复核与下一轮执行计划；本次没有启动新优化、测速或修改运行服务。**

继续以共同仓库 `xiaopangV41FlashCppFromSglangtoXllm` 的 `89a2572fc6c58eebdedb353762939ecd0a0bf0cc` 为起点，使用 SJ9/SJ10、MooreThreads W4AFP8-mt 1017 权重。当前已经是原生 C++ 模型前向，并已接入主要算子族；后续重点是让已接入的算子、缓存、通信和调度协同得更快。不能再把“接入原生 C++”“接入 W4A8 专家”“SWA 单 token 写回”当成尚未完成的任务。

建议的推进顺序是：**恢复可比较的基线与轻量全局计时 → 分清 MCCL 真正通信时间与等待慢 rank 的时间 → 缩短 decode 的通信/索引及缓存整理路径 → mHC、MoE 与 Graph 等按实测收益上限重新排序 → Prefill、并发及更多并行方式。** Graph 是候选项；它与小算子融合存在重叠收益，必须在累计最优版本上复测，不把两者独立收益相加。

现有详细 trace 中，D 端最后三步约 494～503 ms，正式测试 TPOT 为 179.10 ms。因此目前**不能给每个模块编造一个“真实端到端占比”并做精确排名**。本计划给出了有依据的初始排查顺序，并要求 G02 完成轻量计时后，以相同工作负载的可缩短关键路径时间重新排序。测不清的上限写 `unknown`，不写 0，也不拿 profiler 放大的比例充数。
