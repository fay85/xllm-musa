# 分阶段执行计划

## 阶段 A：恢复与测量

1. 阅读README、固定基线、上次实验末尾记录。对最新远端分支只读核验；若有人更新，不覆盖其工作，建立明确的比较提交。先记录现有工作树状态。
2. 建立下一空闲的 `ToDoList_n`，task ID写G01/G02；不把实验编号当优化排名。
3. 检查我方容器和GPU/CPU/NFS的当前状态；确认toolkit是否已更新。固定输入与依赖，在同环境复测I；保留所有失败，不覆盖历史结果。
4. 按G02分服务/设备/各rank轻量计时，记录观测开销；重采短输入和长输入对应窗口。全局概况先覆盖16rank，高开销stack只抓代表窗口。
5. 写出真正可缩短关键路径的上下界、重叠关系和排序变更。对MCCL先测rank就绪偏差，不直接替换通信实现。

退出标准：可以解释当前端到端与设备step的关系；至少对下一候选有可检验瓶颈假设、局部测量和范围。无法测得可信p时明确unknown，并选择最小诊断实验，不能凭图填一个百分数。

## 阶段 B：当前1P1D核心优化

从重排后的核心队列取首个可行项。每项完成以下闭环：

1. **冻结before。** 固定代码、二进制、依赖、input SHA、环境、请求数、正确性容差、指标与停止条件；写预计能影响的环节和Tideal依据。
2. **参考映射。** 找S1～S8的具体文件/提交/函数；确认是否已在当前基线或当前调用。可以复用就调用；必须新增时说明缺口在框架、设备kernel还是MATE接口。
3. **最小修改。** 先最小真实shape及异常边界验证；不同时改模型量化、并行、采样和graph。必要时保留feature flag供A/B。
4. **正确性。** 对cache/index要求逐位；浮点计算做与改动直接相关的短小数值检查；不再以模型固定前缀logits/logprobs一致性验收。通信/状态变更覆盖多rank、跨页、chunk切换、请求重置，禁止只用随机单张量证明完整语义。
5. **筛查与正式测速。** 微基准无收益即可拒绝；有收益后做1暖+5正式的两组。保留每条prompt与输出token、流日志、原始工具报告及实际参数。超时也归档。
6. **trace归因。** before/after同rank、同step、同输入形状和捕获方式；给出CPU/ATen→runtime→GPU链路。需要火焰图时明确是采样耗时、ATen区间还是入口次数；从实际trace渲染，不画一个概念图冒充实测。
7. **比较。** 同时报告局部时间/调用数、TTFT/TPOT/E2E/QPS/output/s、数值误差、显存、失败和波动。上限已知才算兑现率；差异与波动相当时做一次预先记录的交错复验，不挑选最好一轮。
8. **决定。** 成功则更新累计最优及manifest，再估下一项剩余上限；失败保留代码/报告并回到before。若2个case一升一降，说明取舍，不能自行改口径掩盖。
9. **归档提交。** NFS与本地对应；原始大trace按SHA保留；共同仓库个人分支commit，无MR；更新主计划队列与下一步。

“每个算子完成接入都测速”体现在步骤5：算子微基准不取代两组完整测试。已接但没提高性能的候选，不强行启用。低影响文档变化不需要浪费GPU跑整套。

## 阶段 C：并发、缓存和拓扑

阶段B稳定后，按用户本轮已授权推进T10～T14，在SJ9/SJ10同资源预算下扩展吞吐/尾延迟和并行实验：正确的多请求状态隔离→可承受的并发扫点→同总GPU预算的TP/EP/DP/CP对照→更多P/D实例→DSpark等策略。不同布局、Graph、cache与spec组合有多个变量，先单变量或小型正交实验，再组合最优。

不同case不能平均成一个模糊“整体提高X%”；画TTFT/TPOT约束下的吞吐Pareto曲线。领导给SOL口径后补理论模型，不将参考系统的成绩转写为我方保证目标。

## 归因和读图的固定问法

- 观察对象是CPU函数、ATen op、runtime调用、GPU kernel、通信等待，还是服务排队？时间单位、分母是什么？
- 火焰宽度表示时间还是调用次数？父子时间是否重复加了？多stream的重叠是否扣除了？
- GPU空隙的上一条依赖是什么？是主机没发出、等待其他rank、等待缓存，还是采集漏项？
- 如果是memory-bound，真正读写了多少bytes、有效带宽多少、是否反复搬同一cache？如果是compute-bound，shape/精度/有效算力是什么？若两者都低，是否launch/sync受限？
- 优化是减少工作量、提高单kernel效率、减少launch、缩短等待，还是增加批处理摊薄成本？对应全局哪一段缩短？
- 优化前后实际执行路径是否改变？Graph内部是否仍包含慢fallback？是否改变了输出长度、cache命中或采样使“速度提高”？

## 外部协助的最小资料包

仅在确有缺口时填写：需要的具体接口/shape/dtype/layout与scale → 已参考的MATE/交付函数 → 最小输入和数值参考 → 当前错误或实测时间 → 正确性容差 → 全局可收益上限 → 我方能完成的包装/框架部分。缺少driver/graph接口则给capture最小复现；缺少通信能力则给group/bytes/拓扑与就绪偏差。没有真实障碍就写“无”，不要虚构依赖。

最新模型验收仅两道计算题，所有报告注明“仅通过基础功能检查，未完成模型精度验收”；此前更严格模型对分/前缀门槛不再作为晋级条件。
