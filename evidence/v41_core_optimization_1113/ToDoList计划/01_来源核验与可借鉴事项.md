# 来源核验、可借鉴内容与适用边界

资料核验截至 2026-11-12。本文件的来源编号用于待办表。别人模型上的收益是参考证据，不是我方预期收益。只有实际部署调用、数值回归和本机端到端 A/B 才能把候选项变成我方成果。

## S1：DeepSeek 官方原版与 DeepInfer

- 原版 [Hugging Face 模型卡](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017)、[ModelScope 原版](https://modelscope.cn/models/deepseek-ai/DeepSeek-V4.1-Flash-1017)。模型卡要求参考 `encoding/` 与 `inference/`；不要拿平台自动生成的启动片段代替实际模型实现。原版与本任务 W4AFP8-mt 的量化布局不同。
- [DeepInfer](https://github.com/deepseek-ai/DeepInfer)，本次获取 HEAD 为 `a679bb86ce36e883a98a97733492b686e5b9a08e`；[部署 Q&A](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/doc/inference_deployment_qa.md)。来源快照在 `依据/公开来源/`。
- [deepseek-recipe](https://github.com/deepseek-ai/deepseek-recipe)：后续协议/tokenizer 回归的参考；不为优化 token/s 任意改 prompt 编码。

可借鉴：专家负载统计与重排、通信/计算重叠、可变长度 speculative verify、缓存状态的生命周期，以及将量化语义与底层实现分别验证。对应 T01/T04/T08/T10/T13/T14。官方生产 Q&A 的宽 EP 配置与 README 宣称的软件能力要区分：有 CP 功能不等于官方当前生产配置采用 CP。官方 CUDA/Ascend 内核不能直接假定可在 MUSA 上使用。

特别注意 bounded replay：官方 Q&A 明确讨论近似重建的 SWA，官方介绍的尾长与交付版 512 行策略不同。它是缓存/执行策略，不能当作“漏接一个 MATE 算子”，更不能未做精度比较就称等价。

## S2：摩尔线程 SGLang 交付版——当前最直接的实现参考

本地指南：[DeepSeek V4.1 Flash-1017 部署测试指南（11_5）](../../../../DeepSeek%20V4.1%20Flash-1017%20部署测试指南（11_5）.md)。模型：[MooreThreads W4AFP8-mt](https://www.modelscope.cn/models/MooreThreads/DeepSeek-V4.1-Flash-1017-W4AFP8-mt)。本次网页工具不能读取该 ModelScope 页面；模型身份使用此前已下载并逐文件 SHA 核验的固定 revision，未据空页面推断算子。

实际读取的交付代码为 `7c97bb0e6d8b0f8fd41cd797a77b54f7162c79f6`，上级 `01_参考/delivery_sources/`、`sglang_hardware_kernels/`、`sglang_jit_sources/` 有快照和归档 SHA。它比根据环境变量名称猜测更可靠。

| 交付实现位置（相对 delivery_sources/sglang/python/sglang/srt） | 我方可借鉴什么 | 当前状态/限制 |
|---|---|---|
| `layers/attention/deepseek_v4_backend.py`、`layers/attention/dsv4/` | 页索引、candidate、稀疏 Attention metadata、局部 compressor | 当前已接主要数学；继续减少 gather/索引临时张量，T02/T06 |
| `layers/hyperconnection.py`、`layers/communicator_mhc.py` | prenorm、mix、post/combine/norm 及通信组织 | 当前有 MATE prepare 与原生 post，不能称未接 mHC；剩余融合见 T03 |
| `layers/int4fp8_utils.py`、`layers/quantization/quark_int4fp8_moe.py`、`layers/moe/route_quant_handoff.py` | group128 W4A8、路由/量化/专家 GEMM/合并的数据布局 | 当前 W4A8 已接，剩余小 M、分发和负载均衡，T04/T13 |
| `models/deepseek_v4.py`、`deepseek_v4_dspark.py` | CED bounded replay、draft/verify 与状态恢复 | 新执行策略，需独立精度和真实 token 接受率，T10/T14 |

指南中有 Dense block128 开、block32 JIT/MUBIN 关、grouped GEMM 开、CP 局部 compressor、mHC tail chain、full decode graph、DSPARK5 等组合。**环境变量不是可直接粘贴到 xLLM 的功能开关**：要找对应函数、shape、依赖及 capture 合同再迁移。特别是 full graph 部分使用经过验证的兼容库，不能为照搬命令而修改共享宿主机驱动。

指南也有 DP8/EP8 decode 与 CP8/EP8 prefill，因此后续拓扑不局限于 TP8。但当前 C1 原生实现并未自动拥有这些能力。准确率、长上下文、高并发性能分别验收。参考成绩在 `07_并行策略与参考目标.md`。

## S8：领导交流中会改变计划的要求

原 DOCX 的文本提取保存在 `依据/领导记录/`，保留日期；这是用户记录的群聊，不等于已执行的机器状态。

- 11/12：toolkit 安排升级，重新核对环境并测同提交基线；不自行变更系统。
- 11/10～11/11：client/server 同机与跨机、图片 URL、本地文件、冷热缓存都会影响 TTFT。当前做纯文本时也要固定客户端位置、真实 prompt 和 cache。
- chunk 变小可能提高 cache 命中但 TTFT 反而变差；不能只报命中率。所谓 CAR 在聊天中是调度策略上下文，与 Custom AllReduce 不是一个缩写含义，落实前查源码名称。
- 拓扑包含 CP2DP4、DP8、2P1D 等，观察过不均衡和 empty step；这些不能直接移植成 V4.1 可运行配置。
- 8 路 400G 与 GPU/NIC 亲和、不同 rail 子网需按本机实查；`mlx5_9` 是设备标识，不能跨机器硬编码同编号，也不是精度格式。
- 目标包含 TTFT、TPOT、真实输出 token/s；60% SOL 尚无确定计算表。不把 H200 实测乘 0.6 当作 S5000 理论指标。
