# T10～T14：在现有两台服务器内继续推进

本文件是新增范围的实现路线，**不是已完成结果**。验收遵循 `10_1112速度优先验收与扩展到T14.md`。每项仍保存独立目录、直接相关的基本检查、实际成功且 token 数有效的性能数据和 trace；不再追加模型评测集、API 对分、固定前缀数值门槛。仅通过基础功能检查，未完成模型精度验收。

## 已查到的实际限制

当前累计最优原生模型为 `deepseek_v41_native.h` + `deepseek_v41/text_model.h`，尚有 C1、Graph disabled、非 speculative、CP=DP=1、TP=world 的硬检查；EPLB 也明确不支持。这些是当前接入边界，不能仅删除检查就算完成对应功能。先做 T01～T09 能独立衡量的局部改进，再扩展执行和状态管理。

## T10：CED / SWA bounded replay

已核对交付 SGLang 的 `deepseek_v4.py`：从最后一个 KV source 后一层开始只处理尾部 SWA window，配套调整 positions、hidden/pre_mix、Top-K/candidate、Engram 行与 Attention metadata；不是关闭全模型 Attention。SGLang 同时限制完整 prompt hidden/logprobs 的读取。这与本轮无需 prompt logits 的使用方式相容。

我方要在 TextModel 的后半层加入显式尾部选择，在 AttentionRuntime 中同步裁切候选/Top-K 行，保证压缩 KV 来源缓存仍完整，并核验多 chunk 的尾部位置、物理 SWA 写回和跨请求清理。先 q=256 的有界 tail，再 2048 的连续8个 chunk。数值差异记录，不在本轮展开精度排查。该策略主要可能降低 Prefill/TTFT；不能承诺明显降低每 token Decode TPOT。

## T11：前缀缓存与状态复用

先核对 scheduler 现有 prefix cache 是否保存原生模型的所有 cache groups，尤其 compressor recurrent state、Engram 历史与 SWA。命中旧 KV 而遗失这些状态不能算成功。先测试同 prompt 两次、部分公共前缀、不同请求/后缀隔离，观察实际 cached_tokens 和命中后的成功状态。原始 prefix-off 的两组 C1 数据保留；重复前缀工作负载单列，不把缓存命中的短 TTFT 混入原基线。

## T12：多请求与吞吐

原生 Attention、paged table 和 forward 当前都以单请求解释输入。先补每请求的 page table/长度边界、Engram/压缩状态归属，再测试两个不同的简单题同时请求。仅在吞吐数据证明有效后才扩展批量矩阵计算。逐请求串行循环与真正的 GPU batch 必须分别标记。保留 C1 两组回归，再单列 C2/C4 的吞吐、TTFT/TPOT 分位数、每请求实际 token 与错误率。

## T13：并行布局与通信

在当前16卡内，优先试现有代码能表达的 TP4/EP4 与 TP8/EP8 对照，先查权重/缓存显存余量、所有整除条件与实际 rank 数。减少卡数的数据需要明确卡数口径。CP、DP 或 DeepEP 的进一步变化须补齐输入分片、共享专家归约、token dispatch/combine 等语义，不能机械地把各并行数相乘，也不能直接删除 `TP=world` 检查。不能占用 SJ11/12 或已让出的 NVIDIA 卡。

## T14：DSpark / MTP

已经在运行容器的**实际模型视图**读取权重索引，确认包含 `mtp.0`、`mtp.1`、`mtp.2` 及 confidence/Markov head，共3553个匹配键；证据为 `依据/T14_MTP权重资产索引核对_容器视图.json`。这说明当前资产提供了起点，不等于 draft/verify 已接入。首次宿主机直接读取容器绝对 symlink 失败，已保留失败记录并改为容器内读取，不能把首次路径错误当作模型缺少文件。

参考交付 SGLang 的 `deepseek_v4_dspark.py` 和仓库既有 DSpark executor、V4 MTP 路径：先接固定小 block，补 draft 所需 target hidden、各 MTP 权重映射、verify 前后的压缩/Engram/SWA 状态保存与回滚；用人为全拒绝、部分接受、全接受的小状态检查防止越界或重复提交。随后两道计算题与两组成功请求。吞吐只计算真正接受并交付给用户的 token，单列 proposal/acceptance 与 draft/verify 开销。不能把候选 token 当成正式输出，也不能通过关闭拒绝/回滚伪造速度。

目前依赖是我方的执行与状态接入，不因索引已有权重就声称 MTP 已完成。若遇到实际缺少接口，提供最小复现和接口需求，继续下一可行项；不能把本文件的计划写成已实现结果。
