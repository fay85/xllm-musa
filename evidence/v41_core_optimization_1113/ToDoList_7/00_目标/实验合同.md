# T02：同次 decode forward 内复用只读压缩缓存的 materialization

当前代码基线为已验收的 799a93b2；E6 专家通信试验尚未验收，因此先在独立 CPU 工作树准备。正式运行前以 E6 的实际接受/拒绝结果冻结累计最优通信策略。

仅处理 q=1 的 decode：同一 FULL 来源层发布的压缩 KV 和 index cache，在当前 forward 内保持不变；后续 REINDEX/REUSE 层复用一次 gather 的结果。Query、scores、Top-K 与 candidate 仍按原有层规则计算，不跨请求、跨 token 或跨来源层缓存结果。每次 FULL publish 和新 forward 都丢弃只读 view。

保留原 gather 作为开关关闭路径，Prefill 不改变。先测真实 C++ GPU cache view 与原 gather 的位级结果、页边界、padding/NaN、零 committed、新 forward/新来源的数据更新，再做两道计算题。正式测试为 256/256、2048/256 各一暖五正式，核验成功及实际 token 数，profiler 单独抓。

仅通过基础功能检查，未完成模型精度验收。不开展评测集、API 对分、固定前缀 logits 验收。

当前理论依据是重复 gather 次数可下降，尚无该局部在关键路径可消除占比的严格上限；不得将调用次数下降比例当作端到端性能提升。
