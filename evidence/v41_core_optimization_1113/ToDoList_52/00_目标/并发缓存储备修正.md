# C2缓存资源失败与匹配控制修正

v2短输入5次成功，但长输入暖机P端明确报No enough memory to schedule single sequence。8个P rank都已完成最后q512/kv2048层，随后发生资源拒绝；这与E57模型RPC超时不同，不能一律归因MCCL。失败记录和SQL保留，不取失败数据当加速结果。

SWA物理环的估算见kv_cache_estimation.cpp:dsv4_swa_block_count：window_blocks*max_seqs + ceil(max_tokens_per_batch/block_size) + max_seqs +2。此前P/D均按C1的token budget预留SWA，D虽把总缓存改4GiB，SWA池仍由这个公式独立约束；仅增加总缓存字节未必扩大此物理环。

本次先采用已有配置解耦，不新增kernel/改驱动：两端max_tokens_per_batch设4096，P的max_tokens_per_chunk_for_prefill仍512、max_seqs_per_batch仍1，所以P实际仍逐请求q≤512，不能称为4096token矩阵合批；D实际q由请求数1/2/4决定。相同预算用于所有C2/C4 B1控制与batch候选，匹配归因。额外物理SWA储备由现有统一估算器和分配器一致计算。源程序仍f542。

随后必须用两道题、实际输入输出、成功状态和真实q/kv trace复核；不能提前保证该配置解决所有并发问题。若继续失败，保留证据并定位新的具体失败点。
