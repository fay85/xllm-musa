# T07：关闭逐层日志触发/暴露长请求停滞，拒绝晋级

只删除P/D进程的XLLM_DSV41_DIAGNOSTIC_PROGRESS键，仍为同931 ELF、chunk512、P流/FFI/collective fence配置及D mHC等累计开关。已对实际16进程核验环境键确实缺失、实际exe SHA正确，容器默认环境中也没有这个键，避免误把0当关闭。

两道计算题通过。256/256五条实际请求成功，TTFT均值474.63ms、TPOT70.61ms/token；它只是部分有效结果，不是完整两组验收。2048/256暖机成功，正式组0/5成功、5条失败。02:12:54 P的8个execute_model_async达到300000ms RPC超时，主rank CHECK退出。这里的超时是框架等待症状，尚未证明具体是哪一个MCCL/stream依赖出错；也不能推断日志是正确的同步机制。

没有抓after trace，因为正式测试失败。不把失败、短输出或缺失请求当作更快数据。默认恢复已验证的progress=1配置继续后续实验。这个结果表明当前Prefill仍有时序/同步可靠性边界；此前短小通信用例和多次长输入通过，不等于此边界已彻底根治。
