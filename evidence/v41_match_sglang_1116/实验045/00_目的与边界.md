# E45：owner Graph 与 proposal5 的组合

目标仍为21.57ms/token、39.45token/s和TTFT990.04ms。当前冠军仍E39，E44仅READY_DEPENDENCY。

## 来源和假设

冻结SG B使用owner所在DP rank执行TP1 Attention、EP8 LL和DSPARK5；其实际B_decode.sh开启FP8_TP1_LINEAR_OPT/PREQUANT/VERIFY_SPLIT4，源码fp8_utils.py对M=5/6开放TP1特化，对M=6且N/K=4608/5120选择split4。真实B的DP1轻量trace含prequantized及quant_gemm，而非全部走MATE block128。后者限定M=9～128的特定投影或大Prefill，不能盲目替换当前q4/q6。

E41在TP8上proposal5负收益，原因是验证轮数未降低；E44新增完整owner/LL路径且FP8投影使接受行为与旧BF16不同，需一次新组合试验。首轮仅调整proposal3→5；不同时改分块、量化或调度，以免无法判断。

先做q6真实layer0专家重复40次、非owner0行、图外gather、3种输入的Graph与eager检查。它不覆盖完整Attention和缓存，模型仍须两题与短请求。模型正式1暖5、实际256/256、C1、profiler OFF；记录接受/提议、verify轮数、总输出。独立trace在正式之后采集。

若有效工作比或端到端不改善，拒绝这一组合，不能用微基准或单步更快晋级。后续FP8投影分块/融合是另一单独候选。仅通过基础功能检查，未完成模型精度验收。
