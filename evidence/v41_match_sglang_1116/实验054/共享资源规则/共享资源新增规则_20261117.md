# 外部可能抢先用机时，先等待20分钟

用户于2026-11-17补充授权边界：发现我方任务被外部kill、我方容器被外部stop等，视作外部可能需要资源，先等待20分钟，再开始轮询两台资源，直到SJ9/SJ10都释放以后再用。

执行方式：

1. 记录首次发现时间、精确容器和进程身份、退出码/日志、正在执行的请求。正式轮若被中断，保留失败，整轮不计为合格性能结果。
2. 不自动重启。若同一已失效任务的另一端还占GPU，归档后核验归属并尝试正常退出，让出我方资源；异常清理仍遵守既有D态/设备异常停止规则。
3. 将事件和等待截止时间写到NFS根的 `00_control/external_release_cooldown.json`，并在本地恢复记录中保留。重复读取同一事件不把截止时间不断往后延长；另一个独立事件另行记录。
4. 20分钟内不查GPU空闲情况、不启动模型，可以继续CPU代码、文档、离线分析工作。到期以后再只读轮询；两机均空闲后仍需启动前复核。
5. 原因尚不清楚的突然终止先按本条处理。已确认的我方正常主动退出不触发20分钟；已确认内部错误另按故障规程记录与处理。不得把“有人stop了我的容器”理解成重新start的许可。

当前E54 ON在执行，新增规则本身不代表本轮已经发生外部终止事件；没有凭空启动20分钟计时。
