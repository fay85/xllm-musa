# E50 待检验候选：复用 V4 已有的 FP32 累加 Gate GEMV

这是下一项候选的源码核查记录，尚未修改模型、编译新入口或运行GPU测试。

E48低开销诊断显示target+head约47ms/轮，应优先检查target内部；当前trace中FP32小矩阵GEMM重复出现。现有V4内核xllm/core/kernels/musa/deepseek_v4_gate_gemv.cu已经支持token网格Y轴，BF16/FP32输入、保留BF16权重、FP32累加和输出。它由共同仓库0cfd8270整合进入；V4的deepseek_v4_gate.cpp使用它处理小行数，batch_verify较大时选择MATE。当前V4.1 DeepseekV41Gate未接该GEMV，默认仍input转FP32后torch::linear；E31测试的是另一个MATE BF16/FP32 GEMM，不能把其负收益直接套到该SIMT GEMV。

先做隔离原生调用微基准，再决定是否接线。使用真实target384专家×5120和draft128专家×5120权重；覆盖q1/q3/q4/q6、普通/很小输入、非默认流、Graph更换输入。参考当前FP32 linear，比较logits误差、top-k与权重，记录接近并列的路由；不能为接入该kernel把真正FP32权重强转BF16。先验证现成内核，不从零写新kernel。

性能在同进程Graph OFF/ON/反向OFF下测生产调用；局部负收益直接拒绝。若有效，再对模型显式默认关闭开关、保留原始BF16 gate权重、rank一致配置做最小接线与完整构建，从当时累计最佳做基本题、256/256正式与独立trace。该内核不改变EP分片、专家scale、topk算法或共享归约。接受数可能受浮点求和顺序影响，必须记录；不以单kernel快推断整机快。

优先级依据是target热点和已有可复用实现，尚没有校准过的全局Gate占比，不提供精确Amdahl上限。后续仍可考虑共享gate/up与Q-A/KV的verify行批量投影、Norm/RoPE/QDQ融合；E47已有负combine_norm与E46负dot不可原样重跑。
