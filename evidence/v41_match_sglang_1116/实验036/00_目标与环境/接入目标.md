# E36：兼容运行库下的原生 xLLM 控制构建

E35 已验证实际 SGLang DeepEP 的 C++ Tensor 接口、动态 Graph 和空 rank 通信，但尚未接入完整模型。当前累计最佳 E34 为 TPOT 31.51346 ms/token、输出 30.21984 token/s、TTFT 435.32497 ms，未达到最终目标。

当前 xLLM 使用 Torch 2.9.1、MUSA 5.1、MATE 0.2.7；SGLang 实际环境为 Torch 2.9.0、MUSA 4.3.8、MATE 0.2.6。xLLM ELF 显式依赖 libmusart.so.5，不能用 .so.4 冒充 .so.5。先在独立 CPU 构建容器中准备同一源码的兼容产物。以实际 ELF、动态依赖、基础检查和模型控制组验证，不凭 CPU 导入证明 GPU 或模型可用。

临时 CPU 容器：xiaopang1117_v41_sgbuild_sj9。无 GPU 设备，16 CPU/96 GiB 上限；使用冻结的 SG 镜像，复制我方现有源码/构建依赖，不修改原容器、共享镜像、宿主驱动。

先解决构建接口，再验证原模型控制组；之后接入 MATE masked S4FP8 与真正 DP ownership。若环境和代码都变化，应分别测量，不能把环境变化全部归因于代码。E35 成功检查无需重复；只验证本轮新增的产物和接口。

本轮尚无新模型速度结果，不替换累计最佳。仅通过基础功能检查，未完成模型精度验收。
