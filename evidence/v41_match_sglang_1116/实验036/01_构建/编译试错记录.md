# E36 编译试错记录

当前仅建立兼容模型构建环境，不是模型性能改进。

1. 首次 .cu 探针发现 CUDA/MUSA Stream 头重复定义；包装脚本还存在无条件 exit 0，故不能用它的退出状态证明成功。保留 probe_v1_failed.log。
2. 修正隔离容器内 mcc_wrapper 的失败传播。仅把 include 改成 /opt/venv 无效：MusaMapping 插件二进制仍识别 /usr/local/lib/python3.10/dist-packages 的固定前缀。
3. 将固定前缀对应到 SG 实际 Torch2.9.0 包的符号链接后，probe_v3 成功编译 E34 SWA kernel，无 compiler error；没有复制 Torch2.9.1 头冒充2.9.0。
4. 完整构建 full_v1/v2 暴露 SG torch_musa generated 目录打包的旧 protobuf 头遮蔽 xLLM 的3.21头。只调整 include 排序无效。完整构建启动脚本首版误引用 full_v1_v3_finished.json，未启动编译即失败，也保留该错误。
5. 备份并隔离该 CPU 容器下的102个 bundled google 头，以我方原 vcpkg 的同版 protoc/头/库为准。第一次 rename 因 overlay 跨层 EXDEV 未生效，紧接的full_v3仍是相同失败，不能称为新方案；后续 copy+逐文件SHA验证再移出原目录，已完成可恢复备份。
6. full_v4 基于实际完成的头文件隔离启动，进度以 full_v4_job/finished/build.log 及现场 PID/start_ticks 为准。

这些变化只发生在新建的无 GPU 构建容器。原模型容器、原累计最佳 ELF、宿主驱动不变。接下来还必须完成完整链接、依赖核验、基础运行和原模型控制测速；尚未获得新模型速度结果。


7. full_v4 揭示 raw Torch/include 还带一套同样的旧 protobuf。进一步检查实际命令，真正原因是同一个 vcpkg 路径同时以 -I 和 -isystem 出现，编译器将其按 system 目录处理，优先级低于 Torch bundled 头。已去掉该路径的重复 -isystem、保留正常 -I，并恢复先前隔离的102个 google 头；没有保留移走第三方头的方案。
8. full_v5 通过 protobuf，推进77项后因旧 TorchMUSA 无 getPoolUseCount 编译失败。修改 MusaGraphHandle：编译期检测 allocator 方法；有接口时维持已有引用计数核对；无接口时仅允许普通 native Graph，user VMM pool 在 capture_begin 之前明确拒绝。两套实际 TorchMUSA 头的 static_assert 和析构实例化编译均通过。尚未进行 GPU Graph 运行验收。
9. full_v6/v7 中 torch_profiler 等对象通过；旧 SDK CUB 的 placement-new 编译失败。单纯包含 <new> 未解决，已还原本地 causal_conv1d.cu；正在最小纯 device placement-new 样例中定位，后续方案限定在兼容构建，不把无效 include 变更带进主仓库。
10. 测试辅助脚本有一次字符串替换造成语法错误，未执行编译；修正并本地 ast.parse 后，两环境编译检查成功。原失败回执保留。所有构建失败日志独立保存，未重启任何活跃编译任务。

11. device placement-new 最小例最终需要在 MUSA 翻译单元中同时声明 device new/new[]/delete/delete[]，仅放在 __MUSA_ARCH__ 中会遗漏 host pass 声明。该兼容头只对 causal_conv1d.cu 通过 -include 引入，full_v8 已成功编译该对象；未修改模型计算。
12. full_v8 的五个 multimodal TU 仍失败，原因是另一条 vcpkg include 别名仍以 -isystem 出现。实际错误链与命令已保存；v9 将所有 vcpkg_installed/x64-linux/include 的 system 路径统一为普通 -I。先单独编译失败 mm_batch_data.cpp，exit0、无compiler error，再启动完整增量构建。
13. native Graph 小模块 SHA a2df6e6e…，在实际 Torch2.9.0/torch_musa2.9.0+0680da1 单卡通过85次动态输入结果检查、23次注册/重建/释放检查；包含两个图共存和20次创建释放循环。测试正常exit0，临时容器只发TERM后exit0并删除，未使用SIGKILL。此结果不证明完整模型可跑或有性能收益。
