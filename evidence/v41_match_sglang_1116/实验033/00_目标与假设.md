# 实验033：对齐草稿 Markov 相加的 FP32 语义

基于 E30 累计最佳；E31 Gate 默认关闭，E32 Gather 不接入。唯一模型运行变量为 D 侧 `XLLM_DSV41_MARKOV_FP32_LOGITS`。权重、BF16 Markov GEMM、target 模型、proposal3、验证/提交和缓存规则不变。

冻结 SGLang 源码 7c97bb0e6d8b0f8fd41cd797a77b54f7162c79f6：`deepseek_v4_dspark.py::DSparkV4MarkovHead.project_bias` 的 BF16 分支返回 float；分片路径 `BuildStepLocal` 明确把 BF16 bias 和 base 转为 FP32 相加并输出 FP32。environ 默认 MARKOV_W2_BF16=true、TP_SHARD=true。因此不能把差异说成“SG一定用FP32 GEMM”；实际差异是相加结果的数据类型。保存的B运行环境未找到该变量显式覆盖，默认定义只能说明源码选路，不能单独证明每次实际调用。

我方原路径 bias BF16 + base BF16，结果仍 BF16。候选在模型适配层返回 FP32 bias，使既有 sampler 得到 FP32 相加结果。BF16 GEMM 输出不变，near-tie 的提案 token 可改变。这是投机草稿生成策略的有依据候选，不能预先断言接受率提高或目标输出不变；target 验证规则未变，实际结果必须记录。

先使用生产C++ Markov入口及 row_argmax 做24组链式采样、18次动态Graph回放和有意构造的并列边界检查；再模型两道基础题及同ELF OFF/ON 1暖5正式，记录 accepted/proposed/target轮数、输出SHA、真实256/256和全局指标。小收益/波动追加反向控制。独立trace与正式测量分离。只在模型收益验证后晋级。
