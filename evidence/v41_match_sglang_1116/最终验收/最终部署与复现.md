## 2. 直接查看本轮实际启动配置

以[第一轮P配置](原始验收证据/final_short1_v1/roles/sj9/role_config.json)和[第一轮D配置](原始验收证据/final_short1_v1/roles/sj10/role_config.json)为准，含八个rank的完整command/environment。不要仅复制几个Graph环境变量而遗漏专家、cache、通信或动态库配置。

实际流程：主机启动守卫检查两机空闲与编译避让 → docker exec进入对应容器 → 启动`pd_rank_supervisor_nocore_v1.py` → 八个原生C++ rank → P/D控制与状态传递 → SJ10 CPU客户端向服务发HTTP请求。supervisor的实际命令为：

```bash
python3 /expt/scripts/pd_rank_supervisor_nocore_v1.py \
  --config /expt/runs/<新的运行名>/<sj9或sj10>/prepared_config.json \
  --output /expt/runs/<新的运行名>/<sj9或sj10>
```

上述命令只能在前置资源检查之后使用。P/D各8rank，监督进程会记录PID、start_ticks、实际exe、退出码。服务不是运行Python模型forward；Python用于启动、测试、观察和证据归档。

1. 确认任务授权与两台资源。若外部kill/stop我方任务，先避让20分钟；SJ9/SJ10任一台有外部编译都等结束。旧监控已正常退出，须归档旧monitor目录、重新启动只读观察，不能用旧latest.json放行。每10秒采样、至少120秒无编译，启动前再核验GPU/端口/样本新鲜度。
2. 启动上述两个自有容器。以本轮角色配置为模板，另建新的run目录与唯一namespace；仅替换run/namespace/日志路径，保留其余参数。原`final_short*_v1`和`final_long_v1`目录不可覆写。配置生成逻辑见[本轮生成脚本](验收脚本/prepare_final_rounds.py)，启动守卫见[实际启动脚本](验收脚本/final_short1_v1/start_role.py)。

4. 先两道计算题，再正式1暖5；正式端点与统计由[冻结客户端](验收脚本/match_final_client_v1.py)执行。新一次完整验收需要三轮独立重启以及2048/256回归，不能把已有15条充数。脚本中已有输出目录时主动拒绝，是保护原始证据的设计。
