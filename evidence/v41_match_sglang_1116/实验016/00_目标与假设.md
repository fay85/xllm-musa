# 实验016：对齐交付SGLang的静态激活scale与Apertoken GEMM

当前最佳为E13，提交2e3c52b、实际ELF9720e7ef，proposal3/target Graph/静态draft。E15的q4 Graph设备流跨度约67.85ms，必须继续减少target工作；尚未知本候选在正式关键路径中的占比，不预报收益百分比。

## 确认的差异

SGLang B实际日志1006行起：DeepEP LL reuses static activation scale buffers；LL public MATE S4FP8 backend=mutlass, static per-token A scales。源码backend.py的process_weights_after_loading对本地专家的w13/w2 input_scale取max；musa_w4a8_moe.py使用(1,-1)激活recipe。原始checkpoint确有47232个input_scale，抽查layers.0/layers.14/mtp.0的全部专家均为1.0。不能只看config的activation_scheme=dynamic推断在线算子。

我方已有动态group128激活量化、Apergroup GEMM是一个不同的数值路径。候选读取同一权重的input_scale，按SG本地专家取max，使用Apertoken导出；不改变INT4/group128权重及BF16 weight scale。P、D和draft采用同一显式配置。不是换权重或模型，也不是单纯消除同一数学的冗余操作，应记录数值路径变化。

## 实施与检查

默认关闭XLLM_DSV41_W4A8_STATIC_ACTIVATION。Checkpoint离线读取CPU标量；在线分发/量化/SwiGLU/两次GEMM/合并仍在MUSA GPU。Graph以捕获时确定的scale值和固定tensor布局执行。量化kernel增加静态分支，scale由[E,M,K/128]变为[E,M,1]，不会运行时D2H；GEMM显式选择Apertoken而非凭shape猜测。

先CPU构建隔离MATE库、实际xllm、短测模块；再空闲GPU检查真实两专家，M=1/4/6/17/128/256、scale1和0.125、默认/非默认流，量化字节、有效mask、GEMM<=1% RMS、SwiGLU<=0.2% RMS、路由合并和全空专家；真实Graph q1/4/6更换输入与路由三次。通过后进行两道题、独立1暖2快筛、1暖5正式、P路径长输入冒烟和独立trace。小收益按计划反向复测；负收益不替换最佳。
