# 原生prequant接入与真正DP的剩余步骤

当前新增的离线builder与C++kernel入口只提供18个shape的FP8投影；尚未修改模型选路。真正目的仍是为D端DP Attention/DeepEP LL腾出容量，不能用一个微基准通过代替1P1D性能达标。

## 当前实现边界

新增build_dense_prequant_aot.py导出quant/gemm/reduce；deepseek_v41_dense_prequant_block32在当前MUSA stream上调用这些AOT，临时FP8输入、block32 scale、split partial均在GPU。原始FP8权重及scale由调用方提供。构建时Python不等于模型forward回退Python。权重仍未接入loader，新API还不被生产模型调用。

## 下一次代码工作顺序

1. 原生AOT/C++ GPU72检查和动态输入Graph36检查；单卡微基准保留SG与BF16控制。源码、manifest和实际.so SHA对应；编译日志中musamapping环境变量缺失必须归档并在后续构建修正，不能改宿主驱动。
2. 定义可明确区分BF16载体与FP8+scale的权重对象，修改checkpoint加载和AttentionProjection/SharedMlp持有方式。直接在CPU先按权重与scale同一边界分片；FP8路径不保留BF16载体，不偷偷使scale错位。保留O-A grouped BF16；先从支持q1/q4/q6且D-only的显式路径开始。
3. 单算子通过后先测隔离整模型的FP8路径，基础两题、256/256正式与trace，再计算每rank实际参数、cache、Graph池、LL buffer及加载峰值。至少保留足够余量，不只依靠66.83GiB静态值。
4. 把E38已验证的LL路由/专家合并接到模型：C1可先显式固定owner rank，其他rank走空token dispatch和本地专家计算；owner负责完整Attention/shared。记录该受限owner执行，不宣传已支持任意DP调度或并发8。
5. Embedding/Engram为TP8的地方仍需所有rank共同参与，Engram的token历史/表查询和owner hidden上的门控区分开；不能让空rank跳过必要collective。Target LM-head仍TP8，需将owner最终hidden交给各head分片，不能漏算或重复归约。
6. target/draft各自state与SWA/KV/压缩索引、P/D传递、Graph空rank路径、接受/拒绝后回滚仍要完整。不能从E21“每rank复制Attention”冒称已变成DP，也不能把E38单MoE循环冒称全模型LL已接入。
7. 按当前累计最佳控制做正式1暖5，独立trace对比主机step/GPU区间、通信与有效输出工作量。先看真实E2E晋级，不把5.12GiB存储节省直接折算成全局提速。

上述设计是下一步实施路线，只有实际代码、GPU检查和完整模型运行后才更新为完成。
